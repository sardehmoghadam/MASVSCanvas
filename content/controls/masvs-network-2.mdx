## What This Control Means

For your own endpoints, pin the expected certificate or public key so the app rejects connections signed by any other (possibly malicious) CA.

## Why This Matters

Pinning reduces the risk of man-in-the-middle attacks through rogue or compromised CAs for the endpoints you control.

## Main Security Requirement

> The app performs identity pinning for all remote endpoints under the developer's control.

## Common Failure Patterns

- Trusting all default root CAs for your own backend.
- Hardcoding a pinned key with no update path.
- Pinning but leaving a dev bypass enabled in release builds.

## Secure Implementation

Pin SPKI hashes with a backup pin and an update strategy; use platform or library support and test key rotation carefully.

## Key Rules

- Pin only endpoints you control.
- Include a backup pin and a rotation plan.
- Remove debug/pinning bypasses from release builds.

## Checklist for Code Review

- Is pinning scoped to developer-controlled endpoints?
- Is there a backup pin and rotation path?
- Are release builds free of pinning bypasses?
