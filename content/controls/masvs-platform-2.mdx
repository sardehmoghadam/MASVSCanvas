## What This Control Means

WebViews load web content and can expose native functionality through JS bridges; both the content and the bridge must be locked down.

## Why This Matters

A misconfigured WebView can leak local data or let web content call native code, enabling data theft or even code execution.

## Main Security Requirement

> The app uses WebViews securely.

## Common Failure Patterns

- Enabling JavaScript and a bridge for untrusted content.
- Mixing app data into WebView storage or cookies.
- Allowing navigation or file access to arbitrary schemes.

## Secure Implementation

Disable JavaScript when not needed; if required, restrict the bridge to an allowlist of origins and functions, and disable file and universal-link access.

## Key Rules

- Restrict the JS bridge to an allowlist.
- Isolate WebView storage from app data.
- Disable unnecessary file and scheme access.

## Checklist for Code Review

- Is JavaScript and the bridge allowlisted?
- Can untrusted content reach native functions?
- Is file access and link handling restricted?
