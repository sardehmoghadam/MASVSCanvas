## What This Control Means

High-value actions such as transfers, account changes, and reading secrets should re-prompt the user for additional proof such as biometrics, a PIN, or a second factor.

## Why This Matters

If the app is unlocked and unattended, step-up auth prevents an attacker from performing the most damaging actions.

## Main Security Requirement

> The app secures sensitive operations with additional authentication.

## Common Failure Patterns

- Allowing sensitive operations with only the session's ambient state.
- Using a trivially bypassable confirmation like a plain dialog.
- Reusing the same local credential without expiry for step-up.

## Secure Implementation

Gate sensitive flows behind a fresh biometric/pin prompt or a server-side second factor, with a short authorization window.

## Key Rules

- Identify and protect every high-value operation.
- Require fresh, strong re-authentication.
- Keep the authorization window short.

## Checklist for Code Review

- Are sensitive operations behind step-up auth?
- Is re-authentication fresh and strong?
- Is there an expiry on the authorization?
