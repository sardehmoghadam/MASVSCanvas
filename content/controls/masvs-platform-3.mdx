## What This Control Means

Passwords, OTPs, and card details shown on screen must not leak through auto-generated screenshots (the app switcher) or be easily read over a shoulder.

## Why This Matters

Screenshots are captured by the OS automatically, and shared screens or shoulder surfing reveal in-context secrets.

## Main Security Requirement

> The app uses the user interface securely.

## Common Failure Patterns

- Sensitive fields appearing in auto-generated screenshots.
- Masking only visually while firing before-text-change leaks.
- Showing full secrets when a masked view would do.

## Secure Implementation

Set FLAG_SECURE / hide content from screen capture on sensitive screens, and use masked or one-time-reveal fields for secrets and OTPs.

## Key Rules

- Block screenshots on sensitive screens.
- Mask secrets and OTPs by default.
- Reveal concealable data only on demand.

## Checklist for Code Review

- Are sensitive screens excluded from capture?
- Are secrets masked by default?
- Is reveal-on-demand used where possible?
