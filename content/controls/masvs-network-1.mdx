## What This Control Means

Every connection must use TLS with validated certificates and strong ciphers; no cleartext, no trust-all, no disabled verification via low-level APIs or libraries.

## Why This Matters

Network traffic is the easiest thing to intercept; cleartext or broken TLS exposes credentials and user data.

## Main Security Requirement

> The app secures all network traffic according to the current best practices.

## Common Failure Patterns

- Allowing cleartext HTTP.
- Disabling certificate validation or trusting all CAs.
- Using low-level sockets that bypass platform TLS.

## Secure Implementation

Enforce HTTPS, set a network security policy that disallows cleartext, and configure TLS with up-to-date ciphers; on Android use networkSecurityConfig.

## Key Rules

- Never allow cleartext transport.
- Validate certificates by default.
- Do not bypass platform TLS.

## Checklist for Code Review

- Is cleartext traffic disabled app-wide?
- Is certificate validation always on?
- Are ciphers/protocols on an approved list?
