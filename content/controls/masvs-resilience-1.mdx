## What This Control Means

Detect rooted/jailbroken devices (or use platform attestation) because a compromised OS can disable the sandbox, keystore, and other protections the app relies on.

## Why This Matters

Many MASVS controls assume a trustworthy OS; a compromised platform silently defeats them.

## Main Security Requirement

> The app validates the integrity of the platform.

## Common Failure Patterns

- Trusting the platform without any integrity signal.
- Using only easily-spoofed root beacons.
- Not reacting (blocking or degrading) on detection.

## Secure Implementation

Use platform attestation (Play Integrity / App Attestation) plus additional jailbreak/root indicators, and block or degrade sensitive features when integrity fails.

## Key Rules

- Prefer platform attestation over heuristic checks.
- Treat integrity failure as a trust boundary.
- Degrade or block sensitive features on detection.

## Checklist for Code Review

- Is platform attestation used?
- Are integrity results acted upon?
- Do sensitive features require a trusted platform?
